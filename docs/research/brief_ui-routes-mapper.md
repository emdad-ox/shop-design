## 3. Directive syntax as actually used

- **`<sc-if>`** — conditional block. Always `value="{{ boolExpr }}"` plus a design-time `hint-placeholder-val="{{ true|false }}"` telling the editor which branch to preview. Ex: `<sc-if value="{{ isHome }}" hint-placeholder-val="{{ true }}">` (L33), `<sc-if value="{{ cur.canAdd }}" hint-placeholder-val="{{ true }}">` (L194). Nested freely (e.g. isDark/isLight inside the theme button, L44–49). Used both for routes and for tiny inline toggles.
- **`<sc-for>`** — list repeat. `list="{{ arrayField }}" as="itemVar" hint-placeholder-count="N"` (N = design-time placeholder count). Ex: `<sc-for list="{{ items }}" as="item" hint-placeholder-count="6">` (L131), `<sc-for list="{{ navs }}" as="nv" hint-placeholder-count="5">` (L913). Inside, members are read with dotted interpolation: `{{ item.title }}`, `{{ chip.style }}`, `onclick="{{ item.open }}"`.
- **`{{ … }}` interpolation** appears in three positions: text nodes (`{{ cur.title }}`), whole attribute values incl. entire style strings (`style="{{ chip.style }}"` L124, `style="{{ nv.style }}"` L914), and event handlers (`onclick="{{ goProducts }}"`, `onchange="{{ onQ }}"`). Handlers bind to VM functions returned by `renderVals()` (thunks capturing `this.setState`).
- **Literal/numeric binds:** `maxlength="{{ 6 }}"` (L341), `rows="{{ 3 }}"` (L580), `disabled="{{ true }}"` (L244) — the `{{ }}` also carries JS literals, not just field refs.
- **Inputs use `onchange`, not `oninput`** (e.g. L116, L285, L330); handlers read `e.target.value`. Text fields set `dir="ltr"`, `inputmode="numeric"`, and OTP adds `autocomplete="one-time-code"`.
- **`data-*` map hooks (NOT a dc directive — a JS querySelector contract):** static preview maps use `data-addr-map="" data-lat="{{ … }}" data-lng="{{ … }}"` (L442, L564, L794); the interactive picker uses `id="addr-pick-map"` (L893). `manageMaps()` (script L94–139) queries `[data-addr-map]` to mount read-only Leaflet maps (CartoDB `light_all` tiles, custom `pinIcon()` teal SVG marker, all interaction disabled) and mounts the draggable picker on `#addr-pick-map` when `addrSheet==='form'`.
- **`style-hover`** — a custom hover-style directive seen once: `style-hover="transform:translateY(-2px);…"` on the hero CTA (L62).
- **`<helmet>`** — head-injection block (L12–30) holding meta/style/script/link placeholders.
- **NOT PRESENT in this markup:** despite the task brief, I found **no `data-props` and no `data-dc-script`** attributes anywhere in `markup_only.html` (grep-confirmed). If those directives exist they live in the runtime/other template fragments, not this file. The custom attributes that *do* appear here are `<x-dc>`, `<helmet>`, `<sc-if>`, `<sc-for>`, `style-hover`, and the `data-addr-map/data-lat/data-lng` map hooks.

## 4. Icon system, images, reusable patterns

- **Inline SVG only — no raster images.** Every icon is a hand-inlined `<svg viewBox="0 0 24 24" stroke="currentColor" stroke-width≈2>` (Feather/Lucide style). Product/photo imagery is faked with a CSS crosshatch: `background:repeating-linear-gradient(45deg,var(--sur2) 0 8px,transparent 8px 16px) var(--bg)` (seen on every product thumb, detail hero L178, photo tiles L400/L483). Detail hero even carries a mono label "product photo · تصویر محصول" (L179).
- **Data-driven SVG icons:** bottom-nav (`{{ nv.d }}`, L916) and profile menu (`{{ mr.d }}`, L657) render a single `<path d="…">` fed from `navDefs`/`menuRows` path strings in script — one SVG template, many icons.
- **Map marker SVG** is generated in JS: `pinIcon()` (script L87–92) returns an `L.divIcon` with a teal `#0b8a78` pin.
- **Repeated card pattern:** `background:var(--sur);border:1px solid var(--line);border-radius:16px` list rows appear on home/products/cart/detail/orders/requests/addresses/wishlist.
- **Fixed floating CTA pattern:** `position:fixed;bottom:80px;z-index:30;pointer-events:none` wrapper with `pointer-events:auto` button, reused on detail (L235), cart (L306), checkout (L592), refill (L463), used (L518).
- **Radio-dot selector pattern:** `dotStyle` (4px border when selected) reused for delivery, sort, and sheet address rows (script L370, L377, L408).
- **Design tokens** (CSS vars, referenced throughout): `--p` (primary), `--acc`/`--acc-soft`/`--acc-ink` (accent), `--sur`/`--sur2`, `--bg`, `--tx`/`--tx2`, `--line`, `--ok`/`--ok-soft`, `--err`/`--err-soft`, `--warn`/`--warn-soft`, `--glow`, `--shadow`. `--p` is the blue primary (add-to-cart, active tab); `--acc` is the teal used for refill CTA and cart badge.

(`toastAddr` appears defined but I did not see it referenced in this markup — likely dead/for a future screen.)
- **Hardcoded OTP `123456`** with an on-screen hint (`verifyOtp` script L219; markup L343) — auth is a pure mock.
- **Auto-login on mount:** `componentDidMount` sets `loggedIn:true, userName:'کاربر امداد اکسیژن', phone:'0912 845 7455'` unless `props.startLoggedIn===false` (script L71–73). So the app normally boots logged-in; the guest flows only appear after logout.
- **Two hardcoded phone numbers:** services emergency line `0912 845 7455` (L383) — same as the seeded user phone.
- **Discount is a single magic code:** only `EMDAD10` works, hardcoded (script L529).
- **`orders`/`requests` start empty** (script L20) and only populate through `placeOrder`/`completeRefill`/`completeUsed`; all reset on reload (no persistence).
- **Fixed carousel dots** on detail (L181–185) are static markup — the "gallery" never changes; there is only one placeholder image.
- **Checkout delivery method** is a hardcoded non-interactive "هماهنگی تلفنی" radio (L571–577); no shipping options actually exist, and shipping cost is always the text "هماهنگی تلفنی" (cart L296).
- **`cur` never null-fails:** detail falls back to `PRODUCTS[0]` when `pid` is unset (script L339), so the detail route always renders something.
- **8 products, 2 inquiry-only:** `conc` (اکسیژن‌ساز) and `co2` have `price:0, vis:false` → render "استعلام قیمت" instead of price and cannot be added to cart (`showPrice()` script L154; `vm()` L184–195). `nebu` has `stock:0` → shows "ناموجود". `inquire` handler just toasts "درخواست استعلام ثبت شد…" (script L193).
