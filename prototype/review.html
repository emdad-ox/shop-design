Headline findings

These are the five issues that most changed how the product behaves or reads. Two were found by more than one associate.

P0

The "offline" file wasn't offline

The runtime fetched React from unpkg.com at boot, so with the network off the app showed a blank page. Everything else (fonts, GSAP, Leaflet) was already inlined.

Fixed: React 18.3.1 is inlined by build.py. The app boots with all outside requests blocked, over http:// and file://
Head of Design
P0

The design-refactor CSS layer matched nothing

React writes inline styles as font-size: 11px (with a space). Every [style*="font-size:11px"] hook missed, so the Persian 12px floor, the weight ramp, chip heights and the page-entrance stagger were all switched off.

Fixed: hooks now match both forms. 0 text nodes under 12px
Found independently by Associates #1 and #3
P0

The support pill aborted page transitions

The pill used z-index:40, which is also the nav's view-transition-name hook. On Home, Products and Profile the duplicate name threw InvalidStateError, so screens snapped instead of sliding.

Fixed: pill has its own layer (45) and collapses to a round button on scroll
Associate #2
P0

A 0-toman order could be placed

Back after ordering reopened an empty checkout that could still submit. A second Back put a signed-in user on the OTP screen.

Fixed: placeOrder refuses an empty cart; Back is redirected to Cart, and to the screen before login
Associate #2
P1

Primary buttons failed contrast in dark mode

White on --p was 3.45:1 and the hero headline 2.7:1. In light theme the green, amber and teal status text failed AA (2.98 to 4.45).

Fixed: deeper dark gradients, AA light tokens, new --p-ink and --focus tokens
Found independently by Associates #1 and #3

Before and after

Same viewport (390 × 844), same app state, dark theme.

Home. The hero headline went from 2.7:1 to 7.4:1, the primary button text uses the deep primary, and the quick-action tiles are top-aligned.

Products. Chips scroll in one row and no longer push the list down, and the active chip passes AA. The pill shrinks to a circle once you scroll.

Cart. The "added to cart" toast no longer follows you here and covers ادامه و ثبت سفارش.

What shipped, by lens

Visual system Associate #1

  • Normalization hooks match both prop:value and prop: value; the 700→500 notch was dropped so card titles stay stronger than meta text
  • Deeper dark --grad-cta / --grad-brand
  • New --p-ink for primary-as-text, --focus ring token
  • Single-row scrolling chips; product art 96→148px
  • Shadows retinted from old teal ink to the --tx hue
  • Body sets Vazirmatn, so the splash is no longer in Times
  • Placeholder "promo image, place later" copy removed from slide 2

Interaction & flows Associate #2

  • No empty orders; Back is guarded at checkout and after login
  • Toast placed per route and dismissed when the screen changes
  • Support pill: own layer, collapses on scroll (no mis-tap calls)
  • Services card is the 24/7 call action again
  • Past delivery slots disabled; first open slot preselected
  • OTP submits on the 6th digit; the form's phone skips straight to the code step
  • A guest price inquiry asks for a verified phone first
  • A failed submit scrolls to the first error; out-of-stock offers "notify me"

Accessibility & RTL Associate #3

  • Theme toggle named; profile switch is a real role="switch"
  • All inputs labelled, with autocomplete and Persian-digit placeholders
  • Toasts announced through a persistent live region
  • Carousel dots are keyboard buttons; auto-advance pauses on focus and hover
  • scroll-padding keeps focused items clear of the sticky bars
  • Larger cart hit areas; ۱۰ لیتری never splits across lines

Deferred, and verification

Deferred, with reasons

  • One price + تومان treatment. The five variants need four or more template edits that share find-strings with earlier edits. That gets its own pass.
  • Nested interactive product cards. Restructuring the card means touching the card-to-detail morph hook, which is too risky for this pass.
  • Order-success buttons below the fold. You can reach them by scrolling. They fold into the success-screen layout work.
  • Offline map tiles. Bundling a Tehran tile set is a product and size decision. Offline, the map shows only its pin.

Verified

  • build.py is green, with all 99 markup edits at their expected counts
  • Boots with every outside request blocked, over http:// and file://
  • Motion-on tab hops: 0 view-transition errors
  • Add → cart → login → OTP auto-submit → 1 order placed → Back lands on Cart
  • Guest inquiry goes to phone check; a failed refill submit reveals the first error
  • No logic-error banners; the only console errors are the expected map-tile failures
